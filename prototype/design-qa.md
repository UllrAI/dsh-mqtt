# Worker 设置页设计 QA

## 目标

这版原型采用已选定的第三个 DSH 风格方向：把 Worker 当作一个需要被管理的关系节点，而不是聊天时临时切换的模型。页面优先回答三个问题：当前 Worker 能不能用、谁可以控制它、如何添加或撤销控制端。

## 交互检查

- 左侧导航明确标出“远程 Worker”，配置入口位于设置页右上角的“打开配置文件”。
- 首屏直接展示 Worker 身份、可用状态、Broker 连接摘要和可用工作区数量。
- “检查状态”会模拟刷新并打开“运行状态详情”，避免状态只停留在绿色文案上。
- “添加控制端”提供一次性配置的复制动作，并明确说明不会暴露 Worker 模型凭据。
- 待确认请求可进入详情并执行“确认授权”或“拒绝”。
- 已授权控制端可查看权限，或从更多菜单撤销；撤销后列表和数量即时更新。
- “Broker 与高级设置”提供只读配置摘要，避免用户必须阅读 MQTT Topic 或 JSON。
- 移动宽度下导航转为横向滚动，操作按钮和列表仍保持可用。

## 接入边界

当前数据和状态是 UI 原型中的 mock。接入真实 Gateway 时，需要用实际检查结果驱动 Broker、权限、Agent、workspace 和任务容量状态；控制端配置也应改为真实的一次性授权流程。Worker 选择应放在新任务或新会话创建时，普通对话默认使用当前设备，不在每条消息中切换。
